## 定位与平台
- 部门多人共用的工作台/驾驶舱：看清每人工作进展 + 总览各类信息。
- 后台数据源（双源分离）：
  - **任务/工作进展 = WPS 在线表格**（v1.1.0 起从飞书迁移）。
  - **会议室预约 = 腾讯在线表格**（v1.4.0 起新增，用户 2026-08-15 明确要求"会议室读取腾讯表格、其他内容读 WPS"），归属"会务接待"板块。
- 当前约 12 人，名单未定，需支持后期手动增减与修改分工（负责人 = 文本列写人名）。
- 纯静态 HTML 驾驶舱（`行政部驾驶舱_UI_vX.html`）无法直连私有云表格账号；数据靠"复制粘贴/上传CSV"喂入，免授权；"腾讯公开链接自动同步"为最佳努力（跨域常受限，回退提示手工粘贴）。
- **v1.5.0 起新增本地桥接服务（bridge/）实现"实时更新"**：因 WPS/腾讯表均为登录可见私有表，纯网页读不到，故在你**本机跑 Node 服务**(server.js) 用一次性授权拉数据存本地、网页自动读（数据不出本机、不暴露公网）。三种喂数据方式：①网页粘贴框点"上传到本地服务"(推荐,同源无跨域)；②丢CSV到 drop/wps 或 drop/tencent(常开即自动读)；③config.json 填公开链接让服务端抓(best-effort,私有会失败回退)。进阶自动可选：WPS 官方 OpenAPI(fileToken+access_token) 或 两表设「公开可读」。启动：`node bridge/server.js` → 浏览器 `http://localhost:8787`。该服务**非云端**，只在用户本机跑。
- **腾讯会议室表读取方式（v1.6.1 更新，重要）**：表 `docs.qq.com/sheet/DUFNXTnBsV1pGYmZ4?tab=BB08J2`（标题「会议室预约登记表」，file_id `300000000_PSWNplWZFbfx`）确实是**登录可见私有表**——浏览器/服务端 Cookie 爬虫受 401 + CORS 限制。**但 WorkBuddy 内置「腾讯文档连接器」可经官方 API 直读该私有表（无需 Cookie）**：用 tencent-docs 技能 `tdoc_call sheet-mcp get_cell_data`（file_url + sheet_id=BB08J2, return_csv=true）。连接器须先在 WorkBuddy 连上并授权（tdoc_init 返回 READY）。已建小时级自动化「会议室表(腾讯)定时同步到驾驶舱」(automation-1786812677644；旧 automation-1786805823789 于 2026-08-15 被发现已删除，同日重建) 经此直读并写入 bridge/drop/tencent/。纯静态网页仍不可直连；但**助手/自动化经连接器可读**，这是腾讯侧"真自动"的正路。

## 约束
- 敏感信息（工资/身份证/处分）不进表。
- 用户偏"大白话"，沟通与文档避免专业术语。
- **环境约束（v1.6.4 关键，2026-08-15 发现）**：本项目的 bridge 服务(bridge/server.js)在当前 WorkBuddy 环境里是**助手在沙箱内启动**的，不是用户自己机器上常驻的进程。因此"看实时数据"有两种可靠方式：① 让助手 present `http://localhost:8787`（预览面板与沙箱同网，能加载实时页，最稳）；② 用户在**自己机器** `cd bridge && node server.js` 后开本机 `http://localhost:8787`（此时数据源在他们机器）。若用户只是双击打开 `行政部驾驶舱_UI_vX.html` 静态文件，相对路径 `/api/data` 拉不到 → 只看示例版式（v1.6.4 已加绝对地址兜底，但前提是桥接在他们机器跑着）。自动化(腾讯/ WPS 各每小时)写入的 CSV 落在沙箱项目目录，只有当沙箱内的 bridge 服务在跑时才会被读入 /api/data。
