# 行政部驾驶舱 · 项目备忘

## 定位与平台
- 部门多人共用的工作台/驾驶舱：看清每人工作进展 + 总览各类信息。
- 后台数据源（双源分离）：
  - **任务/工作进展 = WPS 在线表格**（v1.1.0 起从飞书迁移）。
  - **会议室预约 = 腾讯在线表格**（v1.4.0 起新增，用户 2026-08-15 明确要求"会议室读取腾讯表格、其他内容读 WPS"），归属"会务接待"板块。
- 当前约 12 人，名单未定，需支持后期手动增减与修改分工（负责人 = 文本列写人名）。
- 纯静态 HTML 驾驶舱（`行政部驾驶舱_UI_vX.html`）无法直连私有云表格账号；数据靠"复制粘贴/上传CSV"喂入，免授权；"腾讯公开链接自动同步"为最佳努力（跨域常受限，回退提示手工粘贴）。
- **v1.5.0 起新增本地桥接服务（bridge/）实现"实时更新"**：因 WPS/腾讯表均为登录可见私有表，纯网页读不到，故在你**本机跑 Node 服务**(server.js) 用一次性授权拉数据存本地、网页自动读（数据不出本机、不暴露公网）。三种喂数据方式：①网页粘贴框点"上传到本地服务"(推荐,同源无跨域)；②丢CSV到 drop/wps 或 drop/tencent(常开即自动读)；③config.json 填公开链接让服务端抓(best-effort,私有会失败回退)。进阶自动可选：WPS 官方 OpenAPI(fileToken+access_token) 或 两表设「公开可读」。启动：`node bridge/server.js` → 浏览器 `http://localhost:8787`。该服务**非云端**，只在用户本机跑。
- **腾讯会议室表读取方式（v1.6.1 更新，重要）**：表 `docs.qq.com/sheet/DUFNXTnBsV1pGYmZ4?tab=BB08J2`（标题「会议室预约登记表」，file_id `300000000_PSWNplWZFbfx`）确实是**登录可见私有表**——浏览器/服务端 Cookie 爬虫受 401 + CORS 限制。**但 WorkBuddy 内置「腾讯文档连接器」可经官方 API 直读该私有表（无需 Cookie）**：用 tencent-docs 技能 `tdoc_call sheet-mcp get_cell_data`（file_url + sheet_id=BB08J2, return_csv=true）。连接器须先在 WorkBuddy 连上并授权（tdoc_init 返回 READY）。已建小时级自动化「会议室表(腾讯)定时同步到驾驶舱」(automation-1786805823789) 经此直读并写入 bridge/drop/tencent/。纯静态网页仍不可直连；但**助手/自动化经连接器可读**，这是腾讯侧"真自动"的正路。WPS 侧仍走本机桥接(OpenAPI/Cookie)。
- 腾讯表真实列（v1.6.1 实测）：标题行「会议室预约登记表」+ 表头 序号/预约日期/时间段/预约人/联系电话/参会人数/会议主题；**无"会议室"列、无"状态"列**；日期 2026.8.12 点分隔；"时间段"合并起止且常含全角冒号。解析时：无会议室列→默认归"会议室"分组、日期/时间归一化、"时间段"拆 start/end。

## 主表「任务总表」字段
任务名称 / 所属大类(单选) / 子项备注 / 负责人(人员) / 协同人(人员多选) / 状态(单选) / 进度%(数字) / 开始日期 / 截止日期 / 优先级(单选) / 堵点说明 / 是否逾期(公式) / 更新时间(公式)。

## 六大类
会务接待、车辆管理、后勤管理、物资采购、行政办公、人力资源；预留"其他"可手动加。

## 视图
看板(按负责人)、看板(按状态)、日历、领导视图(筛选未完成 + 隐藏细节)。

## 仪表盘
总/进行中/已完成/逾期 统计卡 + 完成率进度环 + 各大类条形图。

## 进度表现
数字 + 进度条（用户确认）。

## 版本与备份
- 命名：`行政驾驶舱 v主版本.次版本.修订_日期`（如 v1.0.0_20260815）。
- 加大类(仅加选项)=不改版；加字段/视图/模块=升次版本(v1.1.0)；大改架构=v2.0.0；修显示=v1.0.1。
- GitHub 仓库 `xingzheng-cockpit`（用户 2026-08-15 提供 PAT 后已由助手建好并推送 v1.0.0 tag；v1.0.0–v1.4.0 均在）。
- 换平台(飞书→WPS)记 v1.1.0；加独立 UI 皮肤(5套)记 v1.3.0；加腾讯表格会议室实时模块记 v1.4.0。

## 约束
- 敏感信息（工资/身份证/处分）不进表。
- 用户偏"大白话"，沟通与文档避免专业术语。
