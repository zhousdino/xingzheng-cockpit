# 行政部驾驶舱 · 项目备忘

## 定位与平台
- 部门多人共用的工作台/驾驶舱：看清每人工作进展 + 总览各类信息。
- 后台数据源（双源分离）：
  - **任务/工作进展 = WPS 在线表格**（v1.1.0 起从飞书迁移）。
  - **会议室预约 = 腾讯在线表格**（v1.4.0 起新增，用户 2026-08-15 明确要求"会议室读取腾讯表格、其他内容读 WPS"），归属"会务接待"板块。
- 当前约 12 人，名单未定，需支持后期手动增减与修改分工（负责人 = 文本列写人名）。
- 纯静态 HTML 驾驶舱（`行政部驾驶舱_UI_vX.html`）无法直连私有云表格账号；数据靠"复制粘贴/上传CSV"喂入，免授权；"腾讯公开链接自动同步"为最佳努力（跨域常受限，回退提示手工粘贴）。
- **v1.5.0 起新增本地桥接服务（bridge/）实现"实时更新"**：因 WPS/腾讯表均为登录可见私有表，纯网页读不到，故在你**本机跑 Node 服务**(server.js) 用一次性授权拉数据存本地、网页自动读（数据不出本机、不暴露公网）。三种喂数据方式：①网页粘贴框点"上传到本地服务"(推荐,同源无跨域)；②丢CSV到 drop/wps 或 drop/tencent(常开即自动读)；③config.json 填公开链接让服务端抓(best-effort,私有会失败回退)。进阶自动可选：WPS 官方 OpenAPI(fileToken+access_token) 或 两表设「公开可读」。启动：`node bridge/server.js` → 浏览器 `http://localhost:8787`。该服务**非云端**，只在用户本机跑。
- **腾讯会议室表读取方式（v1.6.1 更新，重要）**：表 `docs.qq.com/sheet/DUFNXTnBsV1pGYmZ4?tab=BB08J2`（标题「会议室预约登记表」，file_id `300000000_PSWNplWZFbfx`）确实是**登录可见私有表**——浏览器/服务端 Cookie 爬虫受 401 + CORS 限制。**但 WorkBuddy 内置「腾讯文档连接器」可经官方 API 直读该私有表（无需 Cookie）**：用 tencent-docs 技能 `tdoc_call sheet-mcp get_cell_data`（file_url + sheet_id=BB08J2, return_csv=true）。连接器须先在 WorkBuddy 连上并授权（tdoc_init 返回 READY）。已建小时级自动化「会议室表(腾讯)定时同步到驾驶舱」(automation-1786812677644；旧 automation-1786805823789 于 2026-08-15 被发现已删除，同日重建) 经此直读并写入 bridge/drop/tencent/。纯静态网页仍不可直连；但**助手/自动化经连接器可读**，这是腾讯侧"真自动"的正路。
- **WPS 任务表读取方式（v1.6.3 更新，重要）**：任务表《行政部驾驶舱模板_v1.1.0.xlsx》(file_id `Rug8vwy4zxMVRwY7Ed56rxPrsqLuHwqka`，云盘显示为"行政部驾驶舱模板_v1.1.0.xlsx")同样为**登录可见私有表**。**v1.6.3 起 WorkBuddy 内置「金山文档(kdocs)连接器」可经官方 API 直读（无需 Cookie / OpenAPI token）**：`mcp__kdocs__sheet.get_range_data`（file_id + worksheet_id=1 + range）。连接器须先在 WorkBuddy 连上（状态 connected）。已建小时级自动化「WPS任务表(金山文档)定时同步到驾驶舱」(automation-1786812677546；旧 automation-1786808634457 于 2026-08-15 被发现已删除，同日重建) 经此直读 → 用 bridge/wps_flatten.py 把稀疏单元格 JSON 拍平为 CSV → 写 bridge/drop/wps/wps_task.csv（桥接每 60s 重读自动刷新）。**注意：这张表目前是空模板（仅表头+逾期公式），待用户往里填任务即自动显示**。WPS 侧旧路径(OpenAPI/Cookie)仍保留在 fetchers.js 作为备选。
- 腾讯表真实列（v1.6.1 实测）：标题行「会议室预约登记表」+ 表头 序号/预约日期/时间段/预约人/联系电话/参会人数/会议主题；**无"会议室"列、无"状态"列**；日期 2026.8.12 点分隔；"时间段"合并起止且常含全角冒号。解析时：无会议室列→默认归"会议室"分组、日期/时间归一化、"时间段"拆 start/end。
- **签证情况模块（v1.9.0 新增，重要）**：用户 2026-08-15 决定——**移除"车辆安排"模块**，把"签证情况"作为 UI 第二项（介于会议室与部门任务之间），且数据来自金山(WPS)表格**新建的"签证"sheet**（非原任务总表的"车辆管理"大类）。**该 sheet 需用户手动在金山表《行政部驾驶舱模板_v1.1.0.xlsx》里新建一个名为「签证」的 sheet**（当前尚不存在，自动化按"找不到即结束不报错"处理 → ②签证显示空态引导）。签证表头列：姓名 / 国家 / 签证类型 / 状态 / 提交日期 / 预计出签 / 有效期至 / 备注（前端/bridge 正则模糊识别，列名可微调）。临期/过期判定基于"有效期至"与今天纯数字比较：已过期→红、临期≤30天→黄；状态徽章 已出签/已拒签/办理中/待续签/未开始。**已建小时级自动化「WPS签证表(金山文档)定时同步到驾驶舱」(automation-1786815070791, HOURLY, ACTIVE)**：经 kdocs 连接器 `get_sheets_info` 按名称定位"签证"sheet → `get_range_data` → wps_flatten.py 拍平 → 写 bridge/drop/visa/visa.csv（桥接每 60s 重读）；只读，不改原表。因既有 bridge 已支持 kdocs 连接器直读，本模块**沿用 bridge 方案**（未切换资料库 skill）。

## 主表「任务总表」字段
任务名称 / 所属大类(单选) / 子项备注 / 负责人(人员) / 协同人(人员多选) / 状态(单选) / 进度%(数字) / 开始日期 / 截止日期 / 优先级(单选) / 堵点说明 / 是否逾期(公式) / 更新时间(公式)。

## 六大类
会务接待、车辆管理、后勤管理、物资采购、行政办公、人力资源；预留"其他"可手动加。

## 视图
看板(按负责人)、看板(按状态)、日历、领导视图(筛选未完成 + 隐藏细节)。

总/进行中/已完成/逾期 统计卡 + 完成率进度环 + 各大类条形图。

## 进度表现
数字 + 进度条（用户确认）。

## 约束
- 敏感信息（工资/身份证/处分）不进表。
- 用户偏"大白话"，沟通与文档避免专业术语。
- **环境约束（v1.6.4 关键，2026-08-15 发现）**：本项目的 bridge 服务(bridge/server.js)在当前 WorkBuddy 环境里是**助手在沙箱内启动**的，不是用户自己机器上常驻的进程。因此"看实时数据"有两种可靠方式：① 让助手 present `http://localhost:8787`（预览面板与沙箱同网，能加载实时页，最稳）；② 用户在**自己机器** `cd bridge && node server.js` 后开本机 `http://localhost:8787`（此时数据源在他们机器）。若用户只是双击打开 `行政部驾驶舱_UI_vX.html` 静态文件，相对路径 `/api/data` 拉不到 → 只看示例版式（v1.6.4 已加绝对地址兜底，但前提是桥接在他们机器跑着）。自动化(腾讯/ WPS 各每小时)写入的 CSV 落在沙箱项目目录，只有当沙箱内的 bridge 服务在跑时才会被读入 /api/data。
